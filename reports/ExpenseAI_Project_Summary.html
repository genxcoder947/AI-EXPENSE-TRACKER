One-line summary ExpenseAI is a frontend-heavy, local-first app. React runs the UI, browser storage supports the demo login/theme flow, Tesseract.js reads receipt images, local rule-based AI suggests categories and insights, and a custom macOS app bundle launches the built site through a localhost server.

1. Executive Summary

  • ExpenseAI is a smart expense tracker built as a React single-page application.
  • The app supports login/sign-up, manual expense entry, optional notes, receipt scanning, AI category suggestions, analytics cards, spending charts, edit/delete controls, and dark/light theme.
  • There is no separate cloud backend or production database in the current project. The app uses browser-side React state and localStorage helpers for the local demo experience.
  • Receipt scanning uses Tesseract.js OCR in the browser and a custom parser that detects totals, merchants, and item-level bill details.
  • The macOS desktop app is a custom .app bundle that starts a localhost server and opens the built site at http://127.0.0.1:8000/index.html.

3. Backend, Database, and Runtime Architecture

Backend and database status Current project backend: no traditional backend API. Current database: no external database such as MySQL, MongoDB, Firebase, or Supabase. The app is a static React build; Vite serves it during development, and the desktop app serves built files through a local HTTP server.
  1. User opens the Vite dev URL or launches ExpenseAI.app.
  2. The browser loads index.html and bundled React assets.
  3. React mounts App.tsx, checks localStorage for theme and any existing expense data, and calls getCurrentUser() to decide whether to show login.
  4. If no user is active, Login.tsx shows the login/sign-up form.
  5. After login/sign-up succeeds in memory, the dashboard renders stats, the expense form, expense list, insights, and charts.
  6. Receipt images are processed in the browser by Tesseract.js; parsed results are copied into the expense form.
  7. The app computes AI suggestions, insights, category totals, and chart slices locally from the expense array.

5. Login Page, Storage, and Data Model

Login Page

  • Login.tsx handles both sign-in and account creation from the same card UI.
  • It validates that the email contains @ and the password has at least 6 characters.
  • The screen uses shared UI components: Input, Button, Label, and Card.
  • The login page switches between "Sign In" and "Sign Up" states using local component state.

6. AI and Receipt Scanning Features

AI Category Suggestions

  • suggestCategory(description) tokenizes the description and compares it with category keyword lists.
  • Supported categories include Food & Dining, Transportation, Shopping, Entertainment, Bills & Utilities, Healthcare, Education, Travel, and Other.
  • The suggestion includes a category, confidence score, reason, matched signals, and a practical action tip.
  • Examples: Zomato, Swiggy, Blinkit, Starbucks, and Domino's map toward Food & Dining; Uber, Ola, fuel, metro, and toll map toward Transportation.

AI Insights

  • generateInsights() calculates category concentration, weekly daily average, projected monthly spend, and practical spending tips.
  • calculateCategoryTotals() computes totals and percentages used by the category charts.
  • Insights currently run locally and deterministically; there is no cloud LLM call.

7. Analytics, Charts, and Animations

  • StatsOverview shows Total Spent, This Month, and AI Categorized. Each card opens a modal with matching expense details.
  • SpendingChart shows top category totals as progress bars.
  • CategoryPieChart renders a custom SVG pie/donut chart with stable category colors.
  • The full chart modal supports Day, Last 24h, Month, and Year filters plus category/description search.
  • src/index.css includes modal fade-in, panel scale-in, pie pop-in, slice drawing, and center-text fade animations.
  • Reduced-motion support disables chart animations for users who prefer less motion.

8. macOS Desktop App Packaging

How the app was made into a Mac app The project was not converted into Electron. Instead, the Vite build was copied into a normal macOS .app bundle. The bundle starts a tiny local server and opens the app URL in the browser, so the user can launch ExpenseAI by double-clicking the app.

Desktop Launch Flow

  1. User double-clicks ExpenseAI.app.
  2. The shell launcher checks whether http://127.0.0.1:8000/index.html is reachable.
  3. If the server is not running, the launcher writes a LaunchAgent plist and starts it.
  4. The LaunchAgent serves the built site from Contents/Resources/site.
  5. The launcher opens the local URL in the default browser.

10. Current Limitations and Production Improvements

  • Use a real backend and database for production, such as Node/Express or serverless APIs plus Postgres, Firebase, or Supabase.
  • Replace localStorage demo auth with secure authentication, hashed passwords, sessions/tokens, and protected user-specific data.
  • Persist expense updates reliably per user. Current source initializes expenses from localStorage but does not write add/edit/delete changes back to localStorage in the active App.tsx.
  • Call setCurrentUser() during login/sign-up if the app should remember the signed-in user after refresh.
  • Improve OCR with stronger image preprocessing, confidence scoring per field, and manual correction history.
  • If true generative AI is needed, add an API-backed assistant for richer natural-language suggestions, budget plans, and anomaly detection.
  • Consider Electron or Tauri later if a fully native app window, menu bar, offline asset control, and stronger desktop integration are required.
